# 正文行距收紧设计

日期：2026-10-29
状态：已确认，待实现
背景需求：「md 文档编写时经常加入换行，希望多个连续换行显示成一个」→ 经澄清，
实际诉求是「整体间距太松，想更紧凑」

## 一、问题澄清（重要）

用户的原始表述指向 Markdown 换行处理，但实测后确认不是那回事：

1. **标准 GFM 本来就会合并连续空行。** 实测 `关于VS的esp-idf...` 源文件里有
   连续 11 个、5 个、3 个空行的位置，渲染成网页后与 1 个空行的效果完全相同，
   只产生一个段落分隔。
2. **33 篇源文档里 `<br>` 标签数量为 0。** 网页上出现的 `<br>` 是 GitHub 把
   单换行转成的硬换行，与「连续换行」无关。
3. 用户最终确认：**诉求是减小整体间距**，不是修改 Markdown 渲染逻辑。

因此本设计**不改动 Markdown 处理链路**（Gmeek.py、journal-markdown.js 均不动）。

## 二、根因

`.jpage.markdown-body` 的 `line-height` 使用令牌 `--journal-body-leading: 1.7`，
而项目还原目标《西北工业大学学报》论文模板实测行距为 **1.37 倍**
（字号 10.4pt，行距 14.2pt）。当前实现比模板松 24%。

这正是「读起来空、一屏字少」的直接原因。

## 三、方案

将 `--journal-body-leading` 从 `1.7` 改为 `1.37`。

```css
:root {
  --journal-body-leading: 1.37;   /* 正文基准行高：对齐论文模板实测值 */
}
```

### 为什么只改一个令牌

该令牌在 CSS 中被三处引用：

| 位置 | 用途 |
|---|---|
| `.jpage.markdown-body` | 分页前的正文容器 |
| `.jpages .jpage` | 分页后的纸页 |

改令牌即三处同时生效，无需逐条修改——这是当初把行距抽成令牌的价值。

### 明确不动的东西

- 段落间距 `0.45em` 保留。截图对比显示：段距压到 `0.2em` 后，本文档靠
  首行缩进 2 字符区分段落，段距过小会使段落边界模糊。
- 标题、列表、引用、图表、代码块的间距全部不动。
- 字号体系不动（已验证与模板一致）。
- 分页引擎代码不动。

## 四、连带影响与验证

行距变紧 → 每页 1300px 可容纳更多文字 → **页数减少**。

分页引擎采用「DOM 顺序分页」（边排边测），不依赖预设页数，因此代码无需改动。
但「内容零丢失」这一保证必须重新验证，因为行距变化会改变每一块的跨界位置。

### 验收标准

1. `--journal-body-leading` 值为 `1.37`
2. 33 篇真实文章：内容零丢失（DOM 逐节点比对）
3. 每篇页数相比改动前减少（符合行距变紧的预期）
4. 单元测试全绿
5. 线上视觉确认：刊头、正文、文末三处行距均变紧

## 五、边界

- 行距收紧后，双栏高度不变（`.jpages .jpage` 固定 1300px），
  引擎的溢出检测逻辑不变。
- 代码块、表格有独立的行距令牌（`--journal-code-leading: 1.55`），
  不受本次改动影响。
