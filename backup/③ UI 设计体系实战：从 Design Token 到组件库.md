# ③ UI 设计体系实战：从 Design Token 到组件库

> AI 生成的 UI 为什么总是"蓝紫色 + 奇怪图标"？怎么让它看起来像一个真正的产品？
>
> 阅读时间：约 14 分钟
> 难度：★★☆☆☆（没经验也能看懂，但需要耐心）

## 这篇文章是给谁看的？

- AI 给你写的界面总是"一眼 AI"——蓝紫色调、奇怪图标、到处都是边框线
- 你翻来覆去跟 AI 说"好看一点"，但它就是改不好
- 同一个 App 里，A 页面圆角 8px、B 页面圆角 16px，看起来不像同一个产品
- 你想知道专业的 UI 设计师是怎么保证所有页面风格统一的

恭喜你，你说的所有问题，都有一个共同的解法——**UI 设计体系**。

---

## 引子：为什么 AI 写的 UI 总是丑？

先看一个真实场景。

你让 AI "帮我做一个报销列表页面"。AI 刷刷刷生成了——你觉得还行。然后你说"再加一个审批页面"——也还行。

但把两个页面放一起：

```text
列表页：蓝色主调、直角卡片、粗体标题
审批页：紫色主调、圆角卡片、细体标题

这两个页面看起来像两个不同的人做的两个不同 App
```

**不是 AI 不努力，是 AI 每次都在重新发明轮子。**

AI 没有"刚才那页用了什么颜色"的记忆，它每次都是"从零开始设计"。所以同一个项目的不同页面，风格总是不统一。

解法就是——**给 AI 一套"积木"，让它只能拼积木，不能自己造积木。**

## 第一章：.UI 设计的三个底层原则

在开始搭积木之前，先理解三条**不可破坏的规则**。

### 原则一：留白——防止 AI 把界面塞满

AI 的默认倾向：只要有空间就继续塞内容。

```text
❌ "看起来宽松一点"（模糊描述 → AI 不会改）
✅ "卡片内边距统一 24px，卡片之间间距 16px，页面左右边距不小于 20px"
   （精确数字 → AI 执行到位）
```

**留白不是浪费空间，是给用户的眼睛喘息的机会。**

### 原则二：一致性——所有页面看起来像同一个 App

AI 最容易犯的错：A 页面按钮圆角 8px，B 页面变成 12px。

```text
✅ 同一类元素在任何地方看起来都一样
✅ 圆角值固定、阴影层级固定、边框有无固定
✅ 图标风格不混用
✅ 直接告诉 AI："所有按钮使用同一套样式，不允许在不同页面自行变化"
```

**这一条能砍掉 70% 的"AI 味"。**

### 原则三：层级——不用边框也能分清主次

"AI 味"界面最明显的特征：**到处都是边框线**。

```text
✅ 用阴影区分"浮起来"的元素
✅ 用背景明度差（深/浅）区分区域，而不是画线
✅ 用字号和字重区分标题/正文/说明
```

专业的界面不用框框，用"视觉重量"来区分主次。

## 第二章：Design Token——设计规范的"原子"

Design Token 是个听起来高大上、其实很简单的概念。

**Design Token = 把颜色、圆角、间距、字号这些"视觉属性"存成有名字的变量。**

### 举个例子

```text
❌ 没有 Token：
  每个页面各自写 #D4A574
  想换主色 → 搜遍所有文件 → 改几百处

✅ 有了 Token：
  定义一次 colorPrimary = #D4A574
  所有页面引用 colorPrimary
  想换主色 → 改这一行 → 所有页面自动变
```

### 一个完整的 Token 体系长这样

```yaml
# 颜色
colorPrimary: "#D4A574"     # 主色（暖棕）
colorBackground: "#FFF8F0"  # 背景（暖白）
colorSurface: "#F5E6D3"     # 卡片底色（米白）
colorText: "#3C2415"        # 文字色（深棕）

# 圆角
radiusCard: 20px            # 卡片圆角
radiusButton: 30px          # 按钮圆角（胶囊形）
radiusInput: 16px           # 输入框圆角

# 间距
spacingPage: 20px           # 页面左右边距
spacingCard: 16px           # 卡片间距
spacingInner: 24px          # 卡片内边距

# 字号
fontTitle: 18px             # 标题
fontBody: 14px              # 正文
fontCaption: 12px           # 辅助文字
```

### 什么时候提取 Design Token？

最佳时机：**AI 生成了一个你满意的页面之后。**

```text
你让 AI 做一个登录页面 → AI 生成 → 你觉得"这个配色好看"
→ 让 AI 提取 Design Token："基于你刚才生成的页面，提取所有设计令牌"
→ 得到 Token 文件 → 后续所有页面引用这个文件
→ 保证后续所有页面和这个页面风格一致
```

这种方法确保你拿到的 Token 源自你已经认可的效果，而不是凭空想象的参数。

## 第三章：shadcn_flutter——别人的组件库，你的参考书

### 传统组件库 vs shadcn 的区别

传统组件库（像 Material UI、Ant Design）：
```text
npm install @mui/material → 引入别人做好的组件 → 几乎不能改样式
```

shadcn 的哲学：
```text
npx shadcn add button → 把按钮源码复制到你的项目 → 你完全拥有它
                       → 你想改成什么样就改成什么样
```

**核心哲学：你不是在使用别人的组件，你是在拥有自己的组件。**

### shadcn_flutter 在 Flutter 中的用法

两个层次：

```text
方式一：当普通包用（最快上手）
  在 pubspec.yaml 添加 shadcn_flutter 依赖
  import 直接用，和你用 Material 组件一样

方式二：当参考源码用（最灵活）
  去 GitHub 看 shadcn_flutter 各组件是怎么写的
  自己照着写一套"你的组件库"
  完全控制样式和行为
```

**方式二才是 shadcn 的真精神**——不依赖别人，自己做一套拥有完整所有权的组件库。

## 第四章：Stitch——用 AI 做 UI 预览

Stitch（stitch.withgoogle.com）是 Google 出的一个 AI 设计工具。

**核心能力：你描述一个界面，它直接生成 Flutter 代码 + 预览效果。**

### 在开发流程中的位置

```text
你的完整 UI 设计体系：

① 定规矩 —— DESIGN_SYSTEM.md
   ↓ 颜色、圆角、字体、间距全写成 Design Token

② 搭积木 —— 基础组件库
   ↓ AppButton / AppCard / AppTextField
   ↓ 用 Design Token 统一风格

③ 验想法 —— Google Stitch
   ↓ 新页面用 Stitch 出设计图
   ↓ 确认好看后，用你的组件库搭出来

④ 搭页面 —— 基于组件库开发
   ↓ 所有页面只用组件库里的零件
   ↓ 不再给 AI 自由发挥样式的机会
```

### Stitch 的精确用法

```text
Stitch 不是"代码生成器"，是"设计探索工具"。

✅ 用它看"好不好看"、"怎么布局"
❌ 不要用它生成最终代码

具体流程：
Step 1 → 打开 Stitch，描述页面需求，看布局效果
Step 2 → 截图保存到你的讨论区
Step 3 → 确认好看后，用自己项目里的组件库搭一遍
Step 4 → AI 只能调用 AppButton / AppCard / AppTextField
         不能自己发明新样式
```

## 第五章：完整实施路线

### 4 周上手路线

```text
第1周：搭好 Design Token + 3 个核心组件
  AppButton（胶囊形按钮）
  AppCard（暖棕+米白卡片）
  AppTextField（圆角输入框）

第2周：玩一玩 Stitch
  去 stitch.withgoogle.com 试试
  上传一张你喜欢的 App 截图，看 Stitch 生成什么
  感受一下 AI 设计的过程

第3周：参考 shadcn_flutter 补组件
  需要新页面 → 去 shadcn_flutter 看对应的组件怎么写
  按你的配色做自己的版本
  每做一个就加到 core/widgets/ 里

第4周之后：形成肌肉记忆
  所有新页面 = 从核心组件库里"拼"出来
  不再让 AI 自由发挥控件样式
```

### 项目文件结构

```text
lib/
├── core/
│   ├── theme/              ← Design Token 集中营
│   │   ├── app_colors.dart
│   │   ├── app_typography.dart
│   │   ├── app_spacing.dart
│   │   └── app_theme.dart
│   └── widgets/            ← 基础组件库
│       ├── app_button.dart
│       ├── app_card.dart
│       ├── app_text_field.dart
│       └── app_dialog.dart
├── data/                   ← 数据层
├── domain/                 ← 业务层
└── presentation/           ← 页面层（只用组件库拼）
```

## 这篇的核心收获

```text
① 三个原则：留白、一致性、层级
② Design Token = 把颜色/圆角/间距存成有名字的变量
③ shadcn 哲学 = 拥有自己的组件，而不是依赖别人的
④ Stitch = 设计探索工具，不是代码生成器
⑤ 完整流程：定Token → 搭组件 → Stitch验想法 → 拼页面
⑥ 先积木后房子，所有页面只用组件库里的零件
⑦ AI 没有自由发挥样式的机会，UI 自然统一
```
